## 1. Миграция данных из нескольких источников (SQL_data_migration)

**Основные компоненты:**

1. **Загрузка данных из источников**
* Создается временная таблица `tmp_sources`, объединяющая данные из 4 разных источников
* Используются операции JOIN для связи таблиц из разных источников
* Собираются все основные данные: заказы, мастера, клиенты, продукты

2. **Обработка справочных данных**
* **Мастера (d_craftsman)**:
  * Обновление существующих записей
  * Добавление новых
  * Ключевые поля: имя и email
* **Продукты (d_product)**:
  * Обновление существующих записей
  * Добавление новых
  * Ключевые поля: название, описание, цена
* **Клиенты (d_customer)**:
  * Обновление существующих записей
  * Добавление новых
  * Ключевые поля: имя и email

3. **Обработка фактовой информации**
* Создается временная таблица `tmp_sources_fact`
* Связываются данные из справочников с фактовой информацией
* Используются ID из справочников

4. **Финальная загрузка фактов**
* Таблица `f_order` обновляется и заполняется
* Ключевые поля для сопоставления: product_id, craftsman_id, customer_id, дата создания заказа
* Обновляются статусы и даты завершения заказов

**Ключевые особенности процесса:**
* Используется механизм MERGE для эффективной обработки как новых, так и существующих записей
* Все изменения маркируются меткой времени загрузки
* Данные проходят через промежуточные временные таблицы для обеспечения целостности
* Реализована логика сопоставления данных из разных источников


## 2. Создание таблицы под витрину данных (DDL_customer_report_datamart) 

**Основные элементы витрины данных:**

* **Ключевой идентификатор** - поле `id` с автоматическим генерированием
* **Основная информация о клиенте**:
  * `customer_id` - уникальный идентификатор
  * `customer_name` - ФИО
  * `customer_address` - адрес
  * `customer_birthday` - дата рождения
  * `customer_email` - email

* **Финансовые показатели**:
  * `customer_money` - сумма расходов клиента за месяц (с учетом -10% для платформ)
  * `platform_money` - доход платформы от покупок клиента

* **Статистика заказов**:
  * `count_order` - общее количество заказов
  * `avg_price_order` - средняя стоимость заказа
  * `median_time_order_completed` - медианное время выполнения заказа

* **Поведенческие метрики**:
  * `top_product_category` - популярная категория товаров
  * `top_craftsman_id` - предпочитаемый мастер
  * Детализация по статусам заказов:
    * `count_order_created`
    * `count_order_in_progress`
    * `count_order_delivery`
    * `count_order_done`
    * `count_order_not_done`

* **Временная привязка** - поле `report_period` для указания отчетного периода

Витрина предназначена для комплексного анализа поведения клиентов, их финансовых показателей и эффективности работы с заказами за определенный период.


## 3. ETL-таблица (DDL_load_dates)

**Основная суть скрипта:**

* Создается специальная таблица для отслеживания **дат загрузки данных** в витрину
* Таблица находится в схеме **dwh**
* Имеет простую структуру с двумя ключевыми полями:
  * **id** - автоматически генерируемый уникальный идентификатор
  * **load_dttm** - дата загрузки данных

**Важные особенности:**
* Таблица спроектирована для **инкрементальных загрузок** (пополнения данными)
* Реализован механизм автоматического создания ID
* Установлено ограничение PRIMARY KEY на поле id
* Предусмотрена возможность удаления существующей версии таблицы перед созданием новой

Эта таблица служит для:
* Отслеживания истории загрузок данных
* Контроля актуальности информации в витрине
* Обеспечения целостности данных при последовательных загрузках

## 4. Инкрементальная загрузка данных (DML_increment_datamart)

**Основные компоненты скрипта инкрементальной загрузки витрины:**

1. **Определение изменений**
* Выявление новых и измененных данных в DWH
* Отслеживание обновлений через временные метки (load_dttm)
* Сравнение с последней датой загрузки

2. **Обработка данных**
* Разделение на **новые записи** (insert) и **обновления** (update)
* Расчет агрегированных показателей:
  * Финансовые метрики (customer_money, platform_money)
  * Статистика заказов (count_order, avg_price_order)
  * Медианное время выполнения заказов
  * Популярность категорий товаров
  * Предпочитаемые мастера

3. **Работа со статусами заказов**
* Отслеживание количества заказов по статусам:
  * created
  * in progress
  * delivery
  * done
  * not done

4. **Механизмы обновления витрины**
* Вставка новых записей
* Обновление существующих данных
* Запись даты последней загрузки

5. **Ключевые особенности**
* Использование оконных функций для определения популярных категорий и мастеров
* Расчет комиссии платформы (10% от суммы)
* Группировка данных по отчетным периодам (месяц)
* Контроль целостности данных через временные метки

Скрипт обеспечивает актуальную инкрементальную загрузку витрины данных с учетом всех изменений в исходных таблицах DWH.
